# Система транзакций для внутреннего процессинга

Отказоустойчивое ядро транзакций для начисления бонусов и переводов между сотрудниками.

## Возможности

- Переводы между кошельками с защитой от race condition
- Автоматическое начисление комиссии 10% при сумме > 1000 u.
- Асинхронная отправка уведомлений через Celery с автоматическим retry
- Атомарные операции (либо все, либо ничего)

## Установка

### 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 2. Применение миграций

```bash
python manage.py migrate
```

### 3. Запуск Redis (для Celery)

```bash
# Windows (Docker)
docker run -d -p 6379:6379 redis:latest

# Linux/Mac
redis-server
```

### 4. Запуск Celery Worker

В отдельном терминале:

```bash
celery -A Test_transactions worker --loglevel=info
```

### 5. Запуск Django сервера

```bash
python manage.py runserver
```

## API Эндпоинты

### POST /api/transfer

Перевод средств между кошельками.

**Запрос:**
```json
{
    "from_wallet_id": "uuid-кошелька-отправителя",
    "to_wallet_id": "uuid-кошелька-получателя",
    "amount": "1000.00"
}
```

**Ответ (успех):**
```json
{
    "success": true,
    "message": "Перевод выполнен успешно",
    "transaction": {
        "transaction_id": "uuid",
        "from_wallet_id": "uuid",
        "to_wallet_id": "uuid",
        "amount": "1000.00",
        "commission": "0.00",
        "status": "completed"
    }
}
```

**Правила комиссии:**
- Если сумма <= 1000 u.: комиссия 0.00 u.
- Если сумма > 1000 u.: комиссия 10% от суммы
- Комиссия автоматически зачисляется на технический кошелек admin

## Тестирование

### Подготовка тестовых данных

Перед запуском тестов необходимо создать тестовые кошельки:

```bash
python create_test_wallets.py
```

Это создаст:
- Кошелек отправителя с балансом 100.00 u.
- Кошелек получателя с балансом 0.00 u.

### Тест 1: Race Condition (Double Spending)

Проверяет защиту от одновременных запросов на списание.

**Запуск:**
```bash
python test_race_condition.py
```

**Что проверяет:**
- Баланс не уходит в минус при параллельных запросах
- Правильное отклонение запросов при недостатке средств
- Атомарность операций

**Параметры теста:**
- 10 одновременных запросов
- По 10.00 u. каждый
- Баланс кошелька: 100.00 u.

**Ожидаемый результат:**
- Все 10 переводов должны быть успешными (или часть, если баланса недостаточно)
- Баланс не должен уйти в минус
- Сумма списаний должна соответствовать количеству успешных транзакций

### Тест 2: Комиссия при переводах > 1000 u.

Проверяет корректность взимания и начисления комиссии.

**Запуск:**
```bash
python test_commission.py
```

**Что проверяет:**
- Комиссия не взимается при сумме <= 1000 u.
- Комиссия 10% взимается при сумме > 1000 u.
- Комиссия зачисляется на admin кошелек
- Атомарность операций (списание, зачисление, комиссия)

**Тесты:**
1. Перевод 500 u. - без комиссии
2. Перевод 1000 u. - без комиссии (порог не превышен)
3. Перевод 1500 u. - комиссия 150.00 u. (10%)
4. Перевод 2500 u. - комиссия 250.00 u. (10%)

**Ожидаемый результат:**
- Комиссия корректно вычисляется и зачисляется
- Все балансы остаются консистентными
- Admin кошелек получает все комиссии

## Защита от Race Condition

Система защищена от double spending через:

1. **Блокировка записей**: `select_for_update()` блокирует строки в БД
2. **Атомарность**: Все операции в `@transaction.atomic`
3. **Проверка баланса**: Выполняется после блокировки, а не до
4. **Retry механизм**: Автоматический retry при блокировках БД

## Комиссия

- **Порог**: 1000.00 u.
- **Процент**: 10%
- **Куда зачисляется**: Технический кошелек admin (создается автоматически)
- **Когда взимается**: Только при сумме перевода > 1000 u.

## Асинхронные уведомления

После успешной транзакции автоматически запускается задача Celery для отправки уведомления:

- **Задержка**: 5 секунд (имитация отправки)
- **Retry**: До 3 попыток при ошибке
- **Задержка между попытками**: 3 секунды
- **Логирование**: Все попытки логируются
